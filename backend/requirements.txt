# Pinned exactly, not with >= bounds.
#
# With lower bounds only, two deploys of the same commit can resolve different
# dependency trees -- so a build that worked yesterday can fail today with no
# change on our side, and the failure appears to come from nowhere. Pinning
# makes a deploy reproducible and makes an upgrade a deliberate, reviewable
# commit rather than an accident of timing.
#
# These are the versions the application is currently running and tested
# against. To upgrade: bump here, run `npm run test:e2e` in frontend/, and
# check /health/ready afterwards.
